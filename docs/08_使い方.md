# 使い方(切り替えと日々の操作)

VBA の `UF検査判定.xlsm` から Web 版に切り替えるときの手順と、毎日の使い方です。
VBA と変わる点は [06_意図した差異.md](06_意図した差異.md)、決めたことは [04_不明点・判断事項.md](04_不明点・判断事項.md) の D1〜D30 にあります。

## 1. 入れる(ラインPCごとに1回)

1. ほかの業務ツールと同じく Python 3.12 と `pip install -r requirements.txt`(Flask・waitress。D1)。
2. 業務ツール統合ランチャーに `Start.vbs` を登録する(D2)。起動するとポート 8800 で開きます。止めるときは画面右上の「終了」。
3. Access の取り込みに Microsoft Access Database Engine(ACE OLE DB 12.0)が要ります(ラインPCには入っています)。

## 2. 最初の設定(設定画面)

| タブ | すること |
|---|---|
| この端末 | 設備名(ライン)と号機を選ぶ。VBA の初期設定 SF3 と同じ。**アクセス権限マスタにこの PC のラインがあれば自動で決まる**(D30)。決まったあとに手で変えるときは管理者パスワード |
| 使用パス | 各フォルダの場所を確かめる。項目ごとにパスは1つ。**仕掛台帳だけ第1パス / 第2パス**(D26)。「確認」で届くかを見る。変えるには管理者の権限と管理者パスワードが要る(アクセス権限マスタから決まらないあいだは管理者パスワードだけ。D30)。「既定に戻す」(項目ごと)・「すべて既定に戻す」で VBA のオンラインの値に戻せる |
| 音 | どこで何を鳴らすかを選ぶ(下の「音の設定」。D29)。管理者パスワードは要らない |
| 権限 | アクセス権限マスタ(梱包資材マスタの「アクセス権限」。all-tools と同じ表)で、この PC に当たった行・決まった権限とライン・読まなかった値・表ぜんぶの点検を見る(D12・D30。下の「権限の設定」) |
| ログ | ログの出力パスを決める。ログは `<出力パス>\ufkensa\` に置かれる([07_ログ.md](07_ログ.md)) |
| 不具合の扱い | VBA の不具合を「再現」か「直す」か。既定はすべて再現(D3) |

仕掛台帳の読み方(D26。この端末の「モード」が効くのは仕掛台帳だけ):

| モード | 読む |
|---|---|
| オンライン | 第1パス(台帳)。第1に無いファイル・第1に無いロットだけ第2パス(控え) |
| オフライン | 第2パスだけ。無ければ「…がありません」 |
| (ロットごと)「控え(第2)から読む」 | モードによらず、そのロットだけ第2パスだけ(下の「ロットを控え(第2パス)から読む」。D28) |

仕掛の DB(SIKALOT / SIKAHIKI / SIKAODR・SIKACOMP / SIKATWOYEAR)は、共有を直接開かず、この PC の手元
(ローカル領域の `cache\kensa_lot`)へ写してから読みます。写し直すのは元のファイルが変わったときだけです。
写せないファイルは読みません(オンラインは第2へ、オフラインは「…がありません」)。写せなかったことはログに残ります。
VBA の「上流の作り直し中は控えを読む」決まり(毎時 59:46〜00:45・PLEASE WAIT.txt)は使いません。

使用パスの主なもの:

| 名前 | VBA | 使いみち |
|---|---|---|
| 仕掛台帳(第1 / 第2) | 第1 = MainPath(台帳)/ 第2 = NextPath(控え) | SIKALOT.sqlite3・SIKAHIKI.sqlite3・SIKAODR.sqlite3(読み方は上の表)。第2はファイル名を変えて置ける(「2つ目の名前」。拡張子を省くと .sqlite3)。SIKACOMP・SIKATWOYEAR は第2 |
| 品証やり取り | QualityPath | 品質基準・伝送用ファイル・包装仕様書の画像 |
| 参照用ファイル | PackingPath | 伝送用ファイルの代わり・VC 種類の画像 |
| 検査履歴 | HistoryPath | ライン別ログ・Aインプット CSV |
| 工場共有 検査データ | FactoryyPath | 梱包検査ﾃﾞｰﾀ(測定DB)・PDF・キャスク/5N |
| 測定データ電子化 | NisPath | hostsend.txt・送信アプリ・result.txt |
| 手元の検査履歴 / 音声 | C:\検査履歴 / C:\VBAWAV | 帳票 PDF の手元保存 / 判定音・案内の音声のフォルダ(何を鳴らすかは 設定 → 音) |
| Edge(PDF 作成) | (新規) | 帳票の PDF をヘッドレス印刷で作る(D7) |

### 音の設定(D29。all-tools 日報ツールと同じ決まり)

音は**ブラウザが鳴らし、どの音を鳴らすかはサーバが決めます**。VBA が鳴らしていた場面(出来事)ごとに、
設定 → **音** で「鳴らさない」か、音声フォルダのファイルを選びます。何も選ばなければ VBA と同じファイルが鳴ります。

- **音声フォルダ** = 使用パスの「音声」(既定 `C:\VBAWAV\`)。音の面の上に「いまどこを見ているか」と中のファイル数が出ます。
  フォルダを変えるのは 使用パス の面です(リンクで移れます)。「確認」でフォルダに届くかを確かめます
- **出来事** は「鳴らす場所 × 意味」です。同じ chime2.wav でも 検査の合格・キャスクの合格・全ヵ所の合格・校正の合格 は別々に選べます
- 選ぶとすぐ保存します。**管理者パスワードは要りません**(間違えても音が鳴らないだけ)。「既定に戻す」で VBA のファイルに戻ります
- 「試聴」は選んであるファイルを鳴らします(音声フォルダの中だけ)
- 受け付ける形式: `.wav` `.mp3` `.ogg` `.m4a` `.aac` `.flac`
- 選んだファイルがフォルダに無いときも選択は残し、「フォルダにありません」と出ます。音は鳴りませんが、画面の文言・判定の表示はいつもどおり出ます
- 開いたばかりの画面は、ブラウザの決まりで一度どこかを押すかキーを打つまで音を鳴らせません。鳴らせなかったときは、その音の文言(「合格」など)を画面の右下に出します

|---|---|---|---|
| 検査 | 合格(kensa_ok)/ 不合格(kensa_ng) | 測定値を判定したとき | chime2.wav / tada.wav |
| 検査 | 対角線(kensa_diag) | 対角線の欄を判定するとき | chimes.wav |

| 検査 | 再印刷しますか / 完了(再印刷)(kensa_reprint / kensa_reprint_done) | 印刷済みのロットの再印刷 | 印刷.wav / 完了.wav |
| キャスク | 合格 / 不合格 / 対角線(cask_ok / cask_ng / cask_diag) | 判定 | chime2.wav / tada.wav / chimes.wav |

設定は端末ごと(`user_settings` の `sound_file_<鍵>`。「鳴らさない」は `鳴らさない` という字)。

### 権限の設定(D30。all-tools 日報ツールと同じ読み方)

権限は **梱包資材マスタ.sqlite3 の「アクセス権限」表**(管理番号 / ログインID / PC名 / 権限 / 有効 / 備考。all-tools と共有)で決まります。

1. 設定 → 使用パス の「アクセス権限マスタ」に、`梱包資材マスタ.sqlite3` のファイル、**またはそのフォルダ**を入れる
   (フォルダなら中の `梱包資材マスタ.sqlite3` を読みます。all-tools の「参照用マスタのフォルダ」と同じ場所)。
2. 設定 → 権限 で、この PC の ログインID・PC名、当たった行、決まった権限・ラインを確かめる。

| 「権限」列 | 意味 |
|---|---|
| `Administrator` | 管理者(使用パス・この端末・取り込み・保守)。`ufkensa:admin`(前の書き方)も同じ |
| `ufkensa:calibration_skip` | 校正をとばせる(このツールだけの値) |
| L-1・LVC・HVC・トット・バランサー | この PC のライン → この端末の設備名(自動) |
| `中板A3`(号機 A1〜A11) | 丸徳・号機 A3。`中板` だけ・`中板3`(日報ツールの書き方)は丸徳にするが号機は決めない |
| それ以外(mode:field・機側・AIM・作業長 など) | 読まない(ほかのツールの値) |

- この PC の行 = **ログインID と PC名 の両方**が当たる行(空欄は問わない・両方空の行は誰の行でもない・大文字小文字/全角半角は問わない・`DOMAIN\user` は `user` でも当たる・有効が 0 / いいえ / 無効 の行は読まない)。1つの欄に「,」「、」「/」「・」「;」で並べられます。
- ライン名は正規の呼び名だけ(文字の幅だけ揃える。`ﾄｯﾄ` = `トット`)。`L1`・`丸徳` などは読まず、権限の面の「表ぜんぶの点検」に「正規は…」と出ます。
- この PC の行に違うラインが2つあるときは決めません(理由が出ます)。表のラインは**前に当てたものから変わったときだけ**当てるので、管理者パスワードで手で変えたラインは表を書き換えるまでそのままです。
- 表に届かないときは、前回読めた結果で動きます。
- **設定の途中**: アクセス権限マスタが未設定・読めない(前回の結果も無い)・表に管理者の行が1つも無いときは、
  画面に「アクセス権限マスタが未設定のため、管理者パスワードだけで設定できます」などと出て、**管理者パスワードだけ**で使用パスを直せます
  (権限の表の場所が使用パスにあるので、新しい PC・試験用の PC で詰まないように)。表が読めるようになれば、パスワード + Administrator の行が要ります。

### 試験用のフォルダから本番に戻す(使用パス「既定に戻す」)

試験のあいだ使用パスを試験用のフォルダへ向けていたときは、設定 → 使用パス の「既定に戻す」(項目ごと。仕掛台帳は第1・第2・2つ目の名前をまとめて)
か「すべて既定に戻す」(画面の確認で、戻る項目と前後の値が出ます)で、VBA のオンラインの値(本番のフォルダ)に戻せます。
モードとログの出力パスは変えません。アクセス権限マスタも既定(空)に戻るので、設定の途中になります(続けて本番の梱包資材マスタを入れてください)。
鍵は使用パスの変更と同じで、ログに前後の値が残ります。

## 3. 切り替えのときに1回だけ(取り込み画面)

1. **Access → SQLite**: 品質基準・伝送用ファイル・梱包検査ﾃﾞｰﾀ などを SQLite に変換する(D4)。仕掛(SIKALOT / SIKAHIKI / SIKAODR)は上流が SQLite で作るので取り込みは要りません(D19)。
   以後、アプリは SQLite だけを読み書きします。
2. **各ラインの xlsm から取り込む**: そのラインの `UF検査判定.xlsm` を選ぶ(D5)。
   保存用・耳用・Lot情報履歴・校正記録・品証検証・印刷履歴・日報・作業中保存 などがこの PC の手元DB に入ります。
3. 取り込んだあとは VBA のブックは使わない(並行して使うと記録が分かれます)。

## 4. 毎日の操作

| 画面 | VBA | 内容 |
|---|---|---|
| 検査 | UF1 | カードで検査員登録 → ロット登録 → 作業選択 → 測定器で入力(判定は自動)→ 印刷・保存 |
| 校正 | UF校正 | 当直の校正が済んでいないと検査画面に「校正を始める」が出る。1000mm → ストレートエッヂ → 記録 |
| 品質基準 | UF品質基準 | ロットの歪・外観・BH・対角・ラテラルボー・要否を参照元つきで見る |
| Aインプット | UFAinput | 梱包高さチェック → Icas 出力(送信の7段階を表示) |
| キャスク | UFCask | 700 枚の表、ゼロ校正、印刷・保存、転送(梱包範囲は スタートNo～エンドNo。D18) |
| 全ヵ所 | UFMitsubishi | 一般 / 5N / 三菱受託 を切り替えて検査(三菱受託は直接選ぶ。D17) |
| 履歴 | UF管理 | この PC で保存した検査を見る。「検査画面へ戻す」で読み込み |

- 測定器の入力は、入力欄にフォーカスが戻るようにしてあります。画面のどこかを押したあとも、そのまま測定器のボタンを押せます。
- VBA の MsgBox は画面の確認窓になります。VBA の `End` で止まっていた所は、止めても画面の状態は残ります(D10)。
- 印刷はブラウザの印刷(既定プリンタ EPSON LP-S180DN。D8)。帳票は HTML で開き、PDF は Edge で作ります。

### ロットを控え(第2パス)から読む(D28。VBA で DBflag に文字を入れていた運用の代わり)

台帳(第1パス)に **ロットが無い・引当が足りない・内容が古い** ときに、そのロットだけを控え(第2パス)の仕掛台帳から読みます。
権限は要りません。押すたびにログに残ります(`kensa.lot_source`)。

1. 検査画面の「ロット」で LotNo の横の **「控え(第2)から読む」** を押す
   - LotNo の欄に別のロットを入れて押すと、そのロットを控えから **Lot登録** します(確認はいつもの Lot登録 と同じ)
   - 欄が空なら、いま登録しているロットを **すぐ控えから読み直します**(「ありません」で読めなかったロットも、もう一度押せば控えで読みます)
2. 読んでいるあいだは、ロット欄の上に **「控えから読んでいます(LotNo)」** が出て、ボタンが「入」になります
3. このロットの仕掛の読み(引当・公差・検番・オーダーNo・歪の厚・Lot情報履歴 など)は、**モードによらず第2パスだけ** から読みます。
   第2にロットが無ければ、オフラインで無いときと同じ扱いです(第1では読みません)
4. **作業保存に残る** ので、アプリを開き直しても続きます。モード(オンライン / オフライン)を切り替えても外れません
   (オフラインで読んだ控えの内容が、オンラインに切り替えて台帳の内容に置き換わることはありません)
5. 外れるのは: もう一度ボタンを押したとき(いまのロットを いつもの読み方で読み直します)・**新規検査**・**別のロットの Lot登録**。
   新しいロットは毎回「切」から始まります
6. 品質基準画面でそのロットを見るとき、キャスク・全ヵ所で同じロットを読むときも、控えから読みます(品質基準画面には「控えから読んでいます」と出ます)

VBA の DBflag と違い、**校正・Min/Max の確かめは飛ばしません**(校正をとばすのはアクセス権限「校正をとばせる」。D27)。

## 5. 困ったとき

- **エラーが出た**: ログのファイル `<ログの出力パス>\ufkensa\ufkensa_<PC名>_<日付>.log` に、そのときの記録(日時・処理・メッセージ・使っていたファイル・直前の処理)が残ります。出力パスは 設定 → ログ で確かめられます。
- **「database is locked」など共有DBに書けない**: 数回やり直してから知らせを出します。続くときは、ほかの PC が測定DB を開いたまま止まっていないか確かめる。
- **仕掛が読めない**: 設定 → 使用パス の仕掛台帳で「確認」を押す。第1・第2 それぞれ、ファイルがあるか・手元へ写せるかが出ます(上流の作り直しの時間帯・PLEASE WAIT.txt は見ません。D26)。
- **PDF ができない**: 設定 → 使用パス の「Edge(PDF 作成)」の場所を確かめる。
- **音が鳴らない**: 設定 → 音 で、その出来事が「鳴らさない」になっていないか・「フォルダにありません」が出ていないかを見る。音声フォルダの場所は「確認」で確かめる。開いたばかりの画面は一度押すまで鳴りません(文言は出ます)。

## 6. VBA と同じ結果かを確かめる(切り替えのあと1回)

xlsm を取り込んだあと、ラインPCで次を実行すると、保存用・耳用に残っている公差(VBA が印刷のときに出した 厚・巾・丈 の -/+)と、
Python で同じロットを登録し直した公差を比べます。

    python scripts\compare_saved_tolerance.py

- 仕掛にまだ残っているロットだけが対象です(仕掛から消えたロットは「仕掛に無い」)。
- 本番の手元DB・測定DB・共有フォルダには書きません(一時フォルダで登録し直します)。
- 結果は `<ログの出力パス>\ufkensa\ufkensa_突き合わせ_<PC名>_<日付>.csv`。「違う」の行は、品質基準がそのあと変わったロットか、
  移植の違いかを1件ずつ見ます。決定 D15(歪公差を検番で引く)は歪の公差なので、この比較(厚・巾・丈)には出ません。

## 保守 → 履歴出力(PDF・xlsx・CSV を試す)

検査を最後まで済ませなくても、印刷のときと同じ保存を試せます。

1. 履歴が無ければ「テスト履歴を入れる」(試験用ロット T999T99 を 1 件、手元DB に入れる)
2. 一覧から履歴を選び「選んだ履歴を PDF 出力」→ 帳票 PDF(Edge)と履歴ブック xlsx を、手元の検査履歴と共有へ
3. 「CSV 出力」→ 履歴 CSV と Lot情報履歴 CSV を、手元と共有へ
4. 書いたファイルの場所が画面の下に出ます。試し終わったら「テスト履歴を消す」(残すと CSV に混ざる)

PDF 出力は手元DB の写しの上で作るので、検査中の画面・保存用・測定DB は変わりません。
テスト履歴は `python tools/make_test_history.py` で作り直せます(試験用の合成データ)。

## ロット情報の読み直しと、更新の案内(2026-11-07)

検査中に、仕掛台帳・引当・オーダー・品質基準(公差の表)が更新されることがあります。

- **読み直す(作業者が任意で)**: 検査画面のロット欄の「ロット情報を読み直す」。いまのロットの情報を読み直し、
  測定値と検査員はそのままで、新しい公差で判定し直します。変わったもの(仕掛・引当・オーダー・品質基準のどれか、
  公差の前後の値)を知らせます
- **更新の案内(自動)**: 検査画面は 1 分ごとに、登録(読み直し)の後に情報が変わっていないかを見ます。変わっていれば
  ロット欄に「ロット ○○ の情報が更新されています(引当・オーダー …)」と「読み直す」ボタンが出ます。
  自動では取り込みません(測定中に公差が黙って変わらないように)
- 見ているもの: 仕掛(そのロットの行)・引当(そのロットの行)・オーダー(引当の受注番号の行)・品質基準(ファイルの更新)

## 共有サーバーに置いて各 PC から起動する(2026-11-07)

- 本体のフォルダを共有に置き、各 PC には `Start.vbs` へのショートカットを配る
- 起動すると、本体を各 PC の手元(`%LOCALAPPDATA%\UFKensa\app\v-<版の印>\`)へ写し、手元の写しから動く
  - 版が変わったときだけ写す(2 回目からは写さない)。手元には 2 つ前までの版を残す
  - 共有の本体を更新しても、動いている PC は手元の写しのまま。次に起動したときに新しい版になる
  - 起動した後は、共有が切れても画面と処理は止まらない(仕掛台帳・履歴など共有のデータの読み書きは共有が要る)
  - 写せないとき(空きが無い など)は、今まで通り共有から動く
- 本体を更新する手順: 保守 → 管理者以外停止 で ほかの PC を止める → 共有の本体を差し替える → お願いを解除する
- 各 PC で書くもの(作業中のデータ・設定・ログ・Python の一時ファイル)は手元。本体のフォルダには書かない
  - Access.log などを共有に集めたいときは 設定 → 使用パス の「Access.log などの置き場所」
- 配布設定(`配布設定\`)は共有の本体のものを見る

## 配布設定(設定 → 配布設定。2026-11-11)

1 台で決めた設定を書き出し、配った先は起動時に読み込む。**その PC で変えた値は上書きしない**
(使用パス・判定の画像の表示・保守の受信機は中を 1 か所ずつ比べ、変えた所だけ残す)。
中身と配った先で起きることは `配布設定\はじめに読む.txt` に書かれる。画面の「置いてある配布設定」に、
読み込んだらこの PC で何が起きるか(入れる / 同じ / この PC の値を残す)と、書き出した版が出る。

- 既定で入れる: 設定ファイルの場所・開く DB・使用パス(判定の画像 OK/NG/診断 も)・判定の画像の表示・音・
  参照の起点・出力先と形式・ログの置き場所と日数・Access.log・再ログイン・管理者パスワード
- 選べば入る(PC ごとの機械・使い方): モード・受信機(COM ポート)・Access 取り込みの元と保存先
- 配らない: ライン(設備名・号機。アクセス権限マスタで当たる)・前回のログイン ID・配色/読み上げ(ブラウザの中)

## 理由選択のマスタ(2026-11-08)

- 測定値の消去・公差外の再測定で出す理由は、伝送用ファイル の表「理由選択」(区分・順番・理由・有効)
  - 区分「消去」= ダブルクリックで消したとき、「再測定」= 同じ位置を 2 回以上再測定したとき
  - 有効 = 0 で出さない。順番の小さい順に並ぶ
- 表が無ければ、VBA と同じ選択肢で自動で作る(検査画面で理由を出すとき・保守 → マスタ管理 で 伝送用ファイル を開いたとき)
- 直すのは 保守 → マスタ管理 → 伝送用ファイル → 理由選択。「板廃棄」(値を戻して異常ロットへ)と「再測定」「その他」(理由の文字が要る)は名前で動きが決まる

## 使用パスを変えたあと(2026-11-08)

- 使用パスを保存すると、読んだ DB・表・公差表の覚えを捨て、次に読むときは新しい場所から読む
- 検査中のロットの公差・規格など、すでに画面に取り込んだ値はそのまま。設定 → 使用パス の「読み込む」で、
  検査中のロットを新しい場所から読み直す(測定値はそのまま。変わった公差は前後の値で知らせる)

## 日報を all-tools の日報モードへ渡す(2026-11-08)

- 印刷のたびに、その直の日報(検査画面の日報シート)を、日報モードが読める CSV で書く
  - ファイル: `集計明細_<日付>_<ライン>_<直>.csv`(例 `集計明細_2026年11月2日_HVC_1直.csv`)。同じ直は上書き
  - 中身: 日報モードの「集計明細」と同じ見出し(日付・ライン・直・ページ・行・ロット№・材・調質・製品寸法 …・作業者)
  - 文字コード: BOM 付き UTF-8
- 置き場所: 設定 → 使用パス の「日報の受け渡し先」(空なら「Access.log などの置き場所」)
- 手で書き出す: 保守 → 履歴出力 →「日報 CSV 出力」
- 日報モードでは「CSV から日報を戻す」でこのファイルを取り込む
