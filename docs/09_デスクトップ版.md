# デスクトップ版(Tauri)の作り(0.3.8〜)

ブラウザで開く代わりに、**専用の窓(UF検査判定.exe)**で動かせます。**ポートを使いません。**
ブラウザ版(`start.bat` / `Start.vbs`)はそのまま残してあり、予備として使えます。
作りは python-web-tools のデスクトップ版と同じです(`src-tauri/`・`bridge.py` はそこから写して名前を変えたもの)。

## 何が何をするか(各言語が得意なことをする)

```
UF検査判定.exe(Rust / Tauri)                  … src-tauri/
 ├─ 窓(WebView2)・帳票の窓・終了の確認
 ├─ 多重起動の防止(2 つ目は今の窓を前に出す。OS のファイルロックでも止める)
 ├─ Python を子として起動・見張り(落ちたら理由の画面。exe を止めれば Python も終わる)
 └─ 画面の要求(app.localhost)を Python の標準入力へ渡す
        │ 標準入出力(1 件 = 見出し 1 行 + 本文)
        ▼
bridge.py(Python)                               … ポート無しの入口
 └─ Flask アプリを WSGI として呼ぶだけ(待ち受けない。waitress は使わない)
        ▼
ufkensa/・app/(Python)                          … 業務(判定・保存・帳票・Aインプット・取り込み・受信機)。変えていない
app/static/js(JS)                               … 画面。別窓を開く所だけ desktop.js 経由
```

| 担当 | 理由 |
|---|---|
| **Rust**: 窓・起動・終了・多重起動・Python の見張り | OS の窓とプロセスを扱うのが得意。exe 1 つで配れる |
| **Python**: 業務の処理すべて | VBA と突き合わせた試験 1,400 件余りがこの形で書かれている。予備のブラウザ版と同じ処理を 1 つだけ持つ。重い処理は無く、書き直す得が無い |
| **JS**: 画面の操作 | 今までどおり。デスクトップ版のときだけ、別の窓・社内サイトを外枠に頼む |

受信機(U-WAVE の COM)・Access の取り込み(cscript → ACE)・PDF(Edge)は、どちらの版でも Python が子のプロセスを使って行います。

## ブラウザ版とデスクトップ版は同時に動かない

起動のとき、どちらの版も同じ錠(`<ローカル領域>\runtime\app.lock`。OS のファイルロック)を取りに行きます(`launch_guard.hold_app_lock`)。

| 先に開いている | 後から開いた | 動き |
|---|---|---|
| ブラウザ版 | デスクトップ版 | 窓に「UF検査判定のブラウザ版がもう動いています…」と次にすることを出して止まる |
| デスクトップ版 | ブラウザ版 | 起動の画面に「デスクトップ版がもう動いています…」と出して止まる |
| デスクトップ版 | デスクトップ版 | 新しく開かず、今の窓を前に出す |
| ブラウザ版 | ブラウザ版 | 今までどおり(開いている画面を前に出す) |

`stop.bat` はどちらの版も止められます(デスクトップ版は窓に「閉じて」と頼み、× と同じ確かめを通って終わる)。

## 動きの約束

| 場面 | 動き |
|---|---|
| 起動 | 窓がすぐ出て「起動しています」→ 待機画面 → 検査の画面 |
| 窓の × / 画面の「終了」 | 実行中の処理があれば訊く(ブラウザ版の「終了」と同じ確認) |
| 帳票(成績票・不良要因票・キャスク・全ヵ所・日報の紙・品質写真) | 別の窓で開く。上の帯の「印刷する」で印刷、「閉じる」でその窓だけ閉じる |
| Python が見つからない・起動できない | 理由と次にすること・ログの場所を窓に出す |
| Python が途中で落ちた | 窓を読み直して理由の画面を出す |

Python は**同梱しません**。各 PC の Python を使います(`python.exe` → `py.exe -3` の順に探す。`UFKENSA_PYTHON` で指定もできる)。
デスクトップ版に要るパッケージは Flask だけです(waitress はブラウザ版用)。ライン PC には WebView2 が要ります(Windows 10/11 には普通入っています)。

## 作り方・配り方

**Windows 版は GitHub Actions が作ります**(`.github/workflows/desktop-windows.yml`)。
Python の試験・Rust の試験・exe の作成・exe を起動しての確認(画面が届く・ポートで待ち受けない・
2 つ目はすぐ終わる・stop.bat で止まる・止めたら Python も残らない)まで流れ、成果物 `UFKensa-windows` に `UFKensa.exe` が入ります。

配るとき: 成果物の `UFKensa.exe` を **`UF検査判定.exe` に名前を変えて**、ツールのフォルダの**直下**(`bridge.py` と同じ所)に置きます。
入れ替えはフォルダごと(ブラウザ版と同じ)。

手元で作るとき(開発機):

```
cd src-tauri
cargo test --release
cargo build --release            # target/release/UFKensa(.exe)
python ../scripts/desktop_smoke.py --exe target/release/UFKensa    # Linux は xvfb-run を前に付ける
```

Linux で作るには WebKitGTK が要ります(`libwebkit2gtk-4.1-dev` など)。

## 置き場所の決まり

- exe は `bridge.py` と同じフォルダに置く(上の階層もたどるので、`src-tauri/target/...` から動かしても見つかる)。`UFKENSA_ROOT` で指定もできる
- 版は `config/app.json`・`src-tauri/tauri.conf.json`・`src-tauri/Cargo.toml` の 3 か所。食い違うと試験(`tests/test_bridge.py`)が落ちる
- 配色・表示の選び方・読み上げ ON/OFF などブラウザに覚えさせているものは、宛先が変わるのでデスクトップ版では初めに既定に戻る(一度選び直す)。使用パス・ラインなどの設定はサーバ側なのでそのまま

## 確かめきれていないこと(Windows の実機で見る)

- 判定の音(wav)が鳴ること
- 帳票の「印刷する」から紙が出ること(WebView2 の印刷ダイアログ)
- キャスクの読み上げで日本語の声が選べること
- Access ファイルを窓に落として取り込むこと
- 受信機(U-WAVE)から値が入ること
