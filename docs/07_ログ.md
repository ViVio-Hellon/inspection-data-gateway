# 07 ログ(all-tools:日報複合ツールと同じ決まり)

## 置き場所と名前

    <ログの出力パス>\ufkensa\
    ├─ ufkensa_<PC名>_YYYYMMDD.log          動作のログ(テキスト。logging)
    └─ ufkensa_記録_<PC名>_YYYYMMDD.jsonl   出来事の記録(1行 = 1 出来事の JSON。画面「ログ」で読む)

- ツールID は `ufkensa`(半角英小文字)。出力パスの直下には置かない。ファイル名は必ず `ufkensa_` で始め、PC 名を入れる
- 出力パスは 設定 →「ログ」で決める(管理者)。決めていない・届かないときは、この端末のローカル `logs\ufkensa\` に同じ形で書く。**ログが書けないことで業務は止めない**
- 前の場所・前の名前のログ(基盤 0.32.0 までの `記録_<PC>_日付.jsonl`)は移さない・消さない・もう書かない。画面で読む・古いものを片付けるときは、前の場所の自分の行も読む
- ほかのツールのフォルダ(nippou\ kanban\ inspection\ dbviewer\ など)は読まない・消さない。古いログを消すのは自分のツールの、この端末のものだけ(残す日数は設定、既定 90 日)
- VBA と同じ書式の業務ログ(`HistoryPath\<ライン>\<ライン>_Log\Access.log` / `Measured.log`)は別に、VBA と同じ場所・書式で書く(`kensa/legacy_log.py`)

## 常に残すもの

| 項目 | 記録 | 出来事(ev) |
|---|---|---|
| 起動・終了 | 時刻・ツール名・版 | `app.start` / `app.stop` |
| 処理の開始・終了 | 処理名・開始と終了・処理時間(ms) | `proc.start` / `proc.end`(**必ず組で**) |
| データ読み込み | 読込先・表・件数・処理時間 | `proc.*`(proc = `db.read`) |
| データ保存 | 保存先・件数・処理時間 | `proc.*`(proc = `db.save` / `import.*`) |
| エラー | 内容・発生箇所・詳細 | `proc.error` / `error.server`(ERROR) |
| 警告 | 想定外の状態・続けたか止めたか | WARN の行(業務上の中断は `proc.end` + `stopped`) |
| 操作履歴 | 画面の操作(書く要求)・開いた画面 | `request` / `screen` / `kensa.<操作>` |

## 処理時間

`trace.timed()` で自動に計る。

| 処理時間 | 重さ |
|---|---|
| 通常 | INFO |
| 3秒以上 / 10秒以上 / 30秒以上 | WARN(`slow` に区切りを書く) |
| エラー | ERROR |

終わらない処理を見つけるため、30秒・1分・2分・5分・10分・20分・30分を過ぎるたびに `proc.slow`(WARN)「まだ終わっていません」を残す。

## エラーのときに必ず残すもの

発生日時(`t`)・ツール名(`app`)・版(`ver`)・PC名(`pc`)・実行していた処理(`procs`)・エラーの種類と文言(`exc.type` / `exc.msg`)・スタックトレース(`exc.tb`)・使っていたファイルや DB(`used`)・直前の処理状況(`recent`。直前15件の出来事)。画面には記録番号(`rid`)を出す。
