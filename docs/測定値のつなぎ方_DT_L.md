# 測定値のつなぎ方(DT と #L)

測定器のボタンを押してから、検査画面の欄に値が入るまでの流れです。
VBA(UF1.INP_Change・FormRelat.PucketMove・Look_Blank・MachineTransfer)の動きを本ツールに移したもので、
2026-11-08〜09 に直した所も含みます。

```mermaid
flowchart LR
  A[測定器] -->|無線| B[受信機<br>U-WAVE-R / DDM-100]
  B -->|1件の文字| C[comport<br>文字に切り分け]
  C --> D[/api/kensa/recv<br>開いている画面へ/]
  D --> E[頭の2文字で種類<br>DT / #L / #〆]
  E --> F[種類ごとの行の範囲で<br>空いた欄を探す]
  F --> G[値を入れる]
  G --> H[検査員・作業選択・校正の確認]
  H --> I[判定・機器の確認<br>保存・公差外]
  I --> J[次の入力欄を黄色に]
```

## 1. 受信機から文字になるまで

| 受信機 | 測るもの | 1 件の区切り | 届く文字の例 |
|---|---|---|---|
| U-WAVE-R(マイクロメーター) | 厚 | CR(改行)で終わる 1 行 | `DT10001+0000015.003M` |
| DDM-100(コンベックス、Bluetooth) | 幅・丈・対角 | STX 〜 ETX で囲んだ 1 件 | `#L1222.8` |

- DDM-100 のパケット形式(`#L` + 長さの 1 バイト + 数字)は、長さのバイトを抜いて `#L1222.8` にします。数字だけで届いたときは、頭に `#L` を付けます(DDM-100 は長さの測定なので #L とみなします)。DDM-100 にはそのたびに ACK を返します。
- 受信機は、受け取った文字を「最後に取りに来た画面」にだけ渡します(検査・校正・Aインプット・キャスク・全ヵ所)。開いていない画面や隠れている画面には入れません。校正で測った値が、知らないうちに検査に入ることはありません。
- 検査・校正などの画面が受け取るのは、保守 → 測定機器ID で足した受信機からです。保守で「検査画面で受け取る」に印を付けたものがあれば、その受信機だけを使います。

コード: `ufkensa/kensa/comport.py`(`split_frames`・`ddm_text`)、`app/routes/kensa.py`(`/api/kensa/recv`)、`app/static/js/recv.js`

## 2. 文字の読み方

| 種類 | 見分け方 | 値 | 機器の番号 |
|---|---|---|---|
| DT | 頭の 2 文字が `DT` | 9 文字目から 11 文字(`0000015.003` → 15.003) | 3 文字目から 5 文字(`10001`) |
| #L | 頭の 2 文字が `#L` | 3 文字目から後ろ全部(`1222.8`) | 持たない |
| #〆 | 頭の 2 文字が `#〆` | 3 文字目から後ろ全部 | 持たない |

- 頭の 2 文字は、全角を半角に、小文字を大文字に直してから見ます。3 文字未満の文字や、頭が DT・#L・#〆 のどれでもない文字は「ﾊﾟｹｯﾄ無し」で、値を入れません。
- DT の機器の番号(例 `10001`)は、マスタ「測定機器ID」の **出力テキスト** と照らし合わせます(4 章)。

コード: `input_router.maker`・`input_router.conv`、`instruments.machin_text`

## 3. どの欄に入るか(DT は厚、#L は幅・丈・対角)

### 3.0 次に入れる欄の表(1 か所)

「値を入れる欄」「〜検査済」「次の入力欄(黄色)」は、どれも **1 つの表** から決めます
(`ufkensa/kensa/input_router.py` の `NEXT_CELL_TABLE`・`SMALL_COUNT_TABLE`・`THIN_TABLE`、引くのは `next_cells`)。
VBA はこの 3 つ(PucketMove・AllCheck・Look_Blank / Look_S_Blank / Smallnumber_Blank)を作業ごとに別々に書いていて、
1 つだけ直すと食い違いました(B60・B90・B91・B93)。2026-11-10(リファクタリング 第3段)に 1 つの表にまとめました。

決まりは次の 4 つだけです。

1. 作業ごとに、行の種類 → その行で値を入れる位置(下の表)
2. 行の範囲: DT = 厚の行、#L = 幅・丈・対角の行、#〆 と黄色の印 = 両方
3. 欄の順: 位置ごとに、行を上から(S1, S2, …, S10, U1, …)。表に無い位置・行は飛ばす
4. 使える欄 = 空で、画面に出ていて(Visible)使える(Enabled)欄

そして、

- **入れる先** = 範囲の中で、最初に使える欄
- **〜検査済** = 範囲の中に、使える欄が 1 つも無い
- **黄色の印** = 厚の行と幅・丈・対角の行の全部で、最初に使える欄

| 作業 | 厚(1〜4 行) | 幅・丈(5〜8 行。極厚は 5〜14 行) | 対角(9〜10 行) |
|---|---|---|---|
| 厚板 | S U C D E | S C E | S C E |
| スラブ | S C(1-上・1-下) | S U C D | S C |
| 極厚(耳付) | S U C D E | S U C D E | (無い) |
| 少枚数(厚板の検番が H でない) | S U C D E | S U C D E | S U C D E |

少枚数(厚板の検番 H)は、検査回数 th で位置を絞ります(`SMALL_COUNT_TABLE`。th は KenCount、KenHBox7 が空なら枚数の計算):

| 検査回数 | 厚 | 幅・丈・対角 |
|---|---|---|
| 5 | S U C D E | S C E |
| 4 | S U C D | S C D |
| 3 | S U C | S U C |
| 2 | S U | S U |
| 1 | S | S |
| 0(KenHBox7 があり KenCount が空) | 測定を止める(「検査回数を入れてください」。下の注) | — |

- 少枚数(厚板の検番 H)で **枚数(KenHBox7)が入っていて検査回数(KenCount)が空(または 0)** のときは、
  DT・#L・#〆・手入力のどれも受けず「検査回数を入れてください」で止めます(2026-11-10。`input_router.ken_count_missing`)。
  VBA は th が 0 になり、何も入らないまま「検査済」になっていました。検査回数は手で入れる欄で、VBA にも枚数から作る決まりはありません
  (UF1:745-765 KenCount_AfterUpdate は入れた検査回数で SmallNumberCount を呼ぶだけ)。
  画面では、このとき検査回数の欄を「検査回数(必須)」として赤枠で出し、枚数を入れたときにも知らせます。

薄板は、検番・山数・検入で位置が決まります(どの行も同じ。`THIN_TABLE`。上から最初に当たったもの):

| 当たるもの | 入れる先・検査済 | 黄色の印 |
|---|---|---|
| 山数 4(6 回) | S U C D E F | S U C D E F |
| 山数 3(5 回) | S U C D E | S U C D E |
| 検番なし | S U C D E | (検番なしは冷延と同じに扱う: 下の行) |
| 冷延(L/N/K/T/S/F)で検入≦25(2 回) | S E | S E |
| 冷延(3 回) | S C E | S C E |
| 検番 H だけ(山数 1・2) | S U C D E(2026-11-10 に黄色の印とそろえた。I5) | S U C D E |

画面に出ていない欄は 4 で飛ぶので、たとえば検番なし・山数 1 の画面(U・D が隠れている)では S → C → E になります。
検番 H・山数 1・2 も同じく S → C → E(厚4ヵ所 で 3・4 行目の U・D が出ているときはそれも)です。

**薄板の検番(頭 1 文字)** は KenNo 欄(DB の検査番号)の頭です。DB にまだ検査番号が無い(空や "0…")ロットは、
ロットを読んだとき(Atu_OPselect)に **最終圧延機から検番の頭を作ります**(`layout.find_priority`。VBA 補助.FindPriority
補助:1455-1491。実績_設備ｺｰｽ を後ろから見て CM1→L、CM2→N、CM3→K、2HI→T、無ければ HOT→H。Q-S-QA-ALL-088)。
VBA は作った頭を作業選択ボタンの表示にしか使わず、次に入れる欄・厚2/4ヵ所・検入では空や "0" のまま見ていたため、
薄板は「検番なし」(5 回)や、どの位置にも当たらない("0" ですぐ「検査済」)になっていました。2026-11-10 から、薄板では
作った頭(`state.ken_head`)を使います(I7。`input_router.ken_no_for_input`・`layout.thin_ken_no`)。
作れなかったとき(実績_設備ｺｰｽ に CM1/CM2/CM3/2HI/HOT が無い)は、VBA どおり「データ上にまだ検査番号がありません」と出て、検番なしのままです。

### 3.1 行の範囲

| 種類 | ふつう(厚板・薄板・少枚数・スラブ) | 極厚(耳付き) |
|---|---|---|
| DT | 厚の行 1〜4。薄板だけ、「厚2ヵ所」ボタンなら 1〜4 行(4 回検査)、「厚4ヵ所」なら 1〜2 行 | 1〜4 行 |
| #L | 5〜10 行(幅 5〜6・丈 7〜8・対角 9〜10) | 5〜14 行(幅 1〜6 = 5〜10・丈 1〜4 = 11〜14、対角なし) |
| #〆 | DT の行 + #L の行 | 1〜14 行 |

- 「厚2ヵ所/厚4ヵ所」は薄板のボタンです。厚板・スラブ・極厚・少枚数は、前の薄板の表示が残っていても 1〜4 行です
  (厚板は 2026-11-09 の B93、スラブ・極厚・少枚数は 2026-11-10 の第3段)。
- 薄板の「厚2ヵ所検査中」(ボタンが「厚4ヵ所」)は、3・4 行目を DT・#〆・黄色の印のどれでも見ません。

### 3.2 位置の順番と、直した所

- 範囲の中に使える欄が無ければ、「DT検査済」「#L検査済」と知らせて、入力先を空にします。そのあとに届いた値は、次の入力先を決め直してから受けます(2026-11-08 に直した所。VBA はフォームの余白を押すまで値を捨てていました)。
- スラブで厚を 1-上 → 1-下 の順に入れるのは、2026-11-08 に直した所です(B90)。VBA は 1-上の厚の次の DT を、幅の欄(U5〜U8)へ入れていました。
- スラブの「#L検査済」は、画面に出ている欄だけで見ます(B91)。
- 厚板の DT は、S厚1〜4 → S1厚1〜4 → 2厚1〜4 → E1厚1〜4 → E厚1〜4 の順です。隠れた欄・使えない(暗い)厚の欄は飛ばし、
  「DT検査済」もそれらを待ちません(B93)。VBA は薄板用の「厚2ヵ所/厚4ヵ所」ボタンの表示で行を決めるため、
  前の薄板や作業保存の読込で「厚4ヵ所」が残ると 1〜2 行しか見ず、S厚2 の次が S1厚1 になって S厚3 へ行きませんでした。
- 2026-11-10(第3段)に表へまとめたときに、次の食い違いも直しました(`tests/fixtures/next_cell_matrix_intended.json` の I1〜I4)。
  - I1: スラブ・極厚・少枚数も、薄板の「厚4ヵ所」が残っていても厚は 1〜4 行(VBA は 1〜2 行で「DT検査済」)。
  - I2: 薄板で隠れた欄に値を入れない(#〆 が「厚2ヵ所検査中」の隠れた 3・4 行目へ、検番なしの DT・#L・#〆 が隠れた U・D へ入っていた)。
  - I3: 黄色の印を隠れた欄に出さない(スラブの E、山数 4 が残った厚板の F、少枚数の回数で隠した欄、再測定の後の薄板 など)。
  - I4: 厚板の #〆 は、黄色の印と同じく C1〜C10・E1〜E10 の順(VBA は C5〜C10 を C1〜C4 より先に見ていた)。
- 2026-11-10(第3段の続き。利用者の決定)で、次も直しました(同じく intended の I5〜I7)。
  - I5: 薄板・検番 H・山数 1・2 は、黄色の印(S1 など)と同じ欄へ入れる。VBA は DT・#L・#〆 がすぐ「検査済」で、印の欄を測れなかった(G1 §11-8)。
  - I6: 少枚数(厚板の検番 H)で枚数があり検査回数が空なら、「検査回数を入れてください」で止める(VBA はすぐ「検査済」)。
  - I7: 薄板で DB に検査番号が無いときは、最終圧延機から作った検番の頭を使う(3.0 の注)。試験は `test_kensa_input_router`・`test_kensa_layout`
    (書き留めの画面は DB の検番も作れる頭も無いので、書き留めは変わらない)。

- 2026-11-11(利用者の決定。intended の I8): 手で欄を押して選んだとき(自動の入力先探しが止まる)も、
  **DT は幅・丈・対角の欄へ、#L は厚の欄へ入れません**。選んだ欄が届いた種類の行でなければ、その種類の行の範囲で
  次に空いた欄(上の表の順)へ入れます(例: S2 を選んで #L が届く → S5 から先の空いた欄)。種類が合う欄を選んだときは、
  VBA どおり選んだ欄へ入れます。#〆(手入力)は選んだ欄へ入れます(変えない)。VBA は自動が止まっていると種類を見ずに選んだ欄へ入れていました。
  (`input_router.manual_target_mismatch`)

コード: `input_router.next_cells`(表を引く)・`input_router.pucket_move`・`input_router.all_check`
試験: `tests/test_next_cell_matrix.py`(作業 × 画面の状態 × 操作の並びで書き留めたもの。`fixtures/next_cell_matrix.json`)

### 3.3 DT と #L が混ざって届いたとき

DT と #L は行の範囲が分かれているので、どちらから測っても、それぞれの範囲の空いた欄に入ります。
厚を全部測ってから幅・丈を測っても、1 枚ずつ厚と幅・丈を交互に測っても、入る欄は同じです。
黄色の欄(次の入力欄)は目安で、届いた種類の範囲が優先されます。

## 4. 値を入れたあと

値を入れたら、次の順に確かめます。止まったときは値を消し、理由を出します。

1. 検査員が登録されているか → 無ければ「検査員登録をして下さい」
2. 作業選択がされているか → 無ければ「作業選択してください」
3. 校正が済んでいるか → まだなら校正の画面を開く(権限で飛ばせる端末を除く)
4. 判定(公差の内か外か)・異常値の確認・機器の確認
5. 作業保存へ書く・公差外の確認

### 機器の確認(DT だけ)

- 届いた DT の機器の番号(出力テキスト)と、マスタ「測定機器ID」から引いた **このライン・この厚(と用途)に合う機器** の出力テキストを比べます。違えば「測定するﾏｲｸﾛを正しく選定して下さい ○○を使用の事」で止めます。
- 合う機器は、ライン(列「ライン」)・厚の範囲(「厚下」〜「厚上」)・用途の条件で引きます。
- #L・#〆 は機器の番号を持たないので、機器は前の DT のまま、帳票のコンベックス欄はラインで決まります(HVC は C11 など)。

コード: `input_router.inp_change`、`instruments.micro_juge`・`instruments.db_return_micro`・`instruments.machine_transfer`

## 5. 次の入力欄(黄色)

値を入れたあと、3.0 の表で次に使える欄を探し、黄色と赤枠にします(入れる先・「〜検査済」と同じ表です)。
厚の行と幅・丈・対角の行の全部を、位置ごとに上から見ます(S1〜S10 → U → C → D → E → F)。
画面に出ていない欄・使えない欄には印を出しません。黄色の欄は、次にその種類の値が入る欄と同じです。

作業ごとの呼び分け(`next_blank`。VBA の Look_S_Blank・Smallnumber_Blank・Look_Blank)は色の付け方だけが違います。
薄板と少枚数(KenCount あり)は、判定表示の抑止(MPEX)中は白・黒枠にします。フォームの余白を押したとき(UserForm_Click)も同じ `next_blank` です。
再測定(NG_Back)の後の印(`look_blank`)も、いまの作業の表で探します。

コード: `input_router.next_blank`・`look_blank`・`look_s_blank`・`smallnumber_blank`(どれも `next_cells` を引く)

## 6. 入らないときに見る所

| 様子 | 見る所 |
|---|---|
| 何も届かない | 保守 → 測定機器ID で受信機を足したか。保守で受信中なら止める(同じ受信機は 1 か所でしか開けない) |
| 届くが「ﾊﾟｹｯﾄ無し」 | 頭が DT / #L ではない。保守 → 測定機器ID の受信記録で、届いた文字を見る |
| 「〜検査済」と出て入らない | その種類の範囲の、出ている欄が全部埋まっている。作業選択(薄板の 厚2ヵ所 / 厚4ヵ所、山数、検入)と 3.0 の表を見る |
| 「ﾏｲｸﾛを正しく選定」で止まる | 測定機器ID の、このラインの出力テキスト・厚下・厚上・用途 |
| 「検査員登録」「作業選択」で止まる | 登録と作業選択 |
| 「検査回数を入れてください」で止まる | 少枚数で枚数が入っている。検査回数(必須の欄)を入れる |
| 薄板で、すぐ「検査済」・欄の数が合わない | 検番(KenNo)。DB に検査番号が無く、最終圧延機からも作れないと検番なしで扱う |

保守 → 測定機器ID の「伝送テスト」では、届いた文字が 1〜5 のどこで止まるかを、実際の値で確かめられます。
