# 06 VBA と意図して変えたところ

業務上の結果(判定・計算・出力項目)は VBA と同じにする方針です。そのうえで、判断事項(docs/04)で決めたことや
Web にしたことで変わる所をここに残します。**ここに無い違いは不具合**として扱ってください。
VBA の既存不具合をどう扱うか(再現 / 直す)は `config/quirks.json` と設定画面「不具合の扱い」にあります。

## Web にしたことで変わる所

| VBA | Web 版 | 理由 |
|---|---|---|
| レジストリの「設備名」「モード」 | 設定画面「この端末」(`user_settings`) | レジストリに依存しない |
| パスはコードに直書き | 設定画面「使用パス」で見て直せる | ご依頼 |
| モード(オンライン/オフライン)ごとにパスの組を持つ。仕掛は MainPath と NextPath の2項目 | 仕掛台帳だけ第1パス(= MainPath)/ 第2パス(= NextPath)。モードは仕掛台帳にだけ効く: オンラインは第1 → 第1に無いファイル・ロットだけ第2(VBA はファイルがあればロットが無くても控えを見ない所がある)、オフラインは第2だけ。ほかの項目はパス1つでモードによらない(VBA のオフラインの値は使わない)。第2はファイル名を変えられる。前の保存は、パス1つの項目はいまのモードで使っていた値、仕掛の第1は旧オンラインの MainPath、第2は旧オンラインの NextPath に読み替える | D26(python-web-tools と同じ考え方) |

## 移植で外したもの(呼び出し元が無い・到達しない・画面だけの処理)

各担当の報告から。根拠は `docs/analysis/` と各モジュールの docstring にあります。

- Judg: Judg_ImageSize(画面の配置だけ)、Test_Tolerance、NflatRewrite(呼び出し元なし)
- OutTolerance: フォームの位置・色付けだけの処理、ConductivLoad の原紙コピー
- AccHIki: Lotflag・AccUpdate 系・Order_Update・Conv(呼び出し元なし)、Arrbox の L60 以降(到達しない)、Micro_Juge_旧
- FormRelat/UF1: ピクセル位置・フォームの大きさ・画像・フォーカス色だけの処理、Load_OP・CBdateCheck・EraseCount_F(呼び出し元なし)
- Input/Worker/Proofreading: ウィンドウとラベルの配置、A保存・Array2D・Daily_Report4_Execution(呼び出し元なし)、コメントアウトされた旧 Height_Check、UFAinput の試験用ボタン、日報＆資材計算.xlsm のマクロを呼ぶボタン、UFNameList の VBA 停止
- QP_DB/Quality_DB: 旧 Quality(D9)、BoColor(画面の色だけ)、Reload 系(キャッシュの読み直しで代わる)

## 試験データについて

受領した Access から試験データを作るとき、変換の道具(mdbtools)が**長さ0の文字列を Null と同じに書き出していた**。
必須(NOT NULL)の文字列の列は Access では Null になり得ないので、"" に戻した(VBA が読む値と同じ)。

## 2026-11-06 追加

## 2026-11-10 リファクタリング 第2段: 仕掛台帳の第1/第2の読み分けを 1 か所に

仕掛台帳(SIKALOT / SIKAHIKI / SIKAODR)の第1/第2の読み分けを `ufkensa/kensa/lot_ledger.py` 1 か所にまとめた。
Arrbox・AccReflec・Lot情報履歴の保存(HistorySave)・SikaAtuCreate・厚の作業選択の引当・品質基準の引当(HikiArrCreate)・
包装仕様の注意文(MaterialsMsgBox)・ロット情報の見張り・名前で引く台帳の場所(`paths.db_file`)が、みな同じ決まりで読む。

| 読み方 | まず読む側 | 次に見る側 |
|---|---|---|
| オンライン | 第1 | 第2 |
| オフライン・「控えから読む」 | 第2 | 第1 |
| オンラインで DBflag(VBA) | 第2(NextPath)だけ | なし |

1. まず読む側のファイルが読めない(無い・手元へ写せない)→ 次に見る側のファイル
2. まず読む側にロット(条件の行)が無い → 次に見る側の行(列の並びはまず読む側に直す)
3. まず読む側の表が空 → 次に見る側の列名
4. 引当: 次に見る側にだけある引当番号の行を足す(「…に無い引当を…から足しました」)
5. オーダー: 引当の受注番号のうち、まず読む側に無いものを次に見る側から足す
6. 第2の台帳に無い列は、第1の同じロットの行で補う

決まりは前から Arrbox(検査画面)がこのとおりで、ほかの読み手がそれぞれ少しずつ違っていた。そろえて直ったもの
(`tests/fixtures/lot_ledger_matrix_intended.json` に 60 通り、理由つき):

- SikaAtuCreate: 第1のファイルが無いと止まっていた(DbMissing)。オフラインで第2に無いロット・ファイルを第1で見なかった
- Lot情報履歴の SIKAODR: 引当を読んだ側の SIKAODR だけを読んでいた。いまは引当をどちらから読んでも、まず読む側の SIKAODR に
  足りない受注を次に見る側から足す(オフラインで第2に無い受注も第1から)。第1の SIKAODR が無いと止まっていた(DbMissing)のも直した
- Lot情報履歴: Test のロットでも、第1に無ければ第2を見てから「何もしない」を決める(前は第2を見る前に抜けていた)。
  オフラインで第2のファイルが無く第1へ移り、そこにもロットが無いときの文言は「SIKAHIKINOW.accdbに…ﾃﾞｰﾀがありません」
  (NextPath の文言。前は「LOT一覧：LOTNO有_HIKIDB：LOTNO無」)
- 包装仕様の注意文(MaterialsMsgBox): 受注が第1に無いとき第2を、オフラインで第2に無いとき・第2のファイルが無いとき第1を見る
- ロット情報の見張り: 第1の SIKAODR が無いとオーダーを比べていなかった。オフラインで足りない受注を第1から足す
- 品質基準の引当(HikiArrCreate): 検査画面の引当と同じく、次に見る側にだけある引当も足す。オフラインで第1を見る
- 名前で引く台帳の場所(全ヵ所・キャスク・保存の確かめ): オフラインで第2のファイルが無ければ第1

MaterialsMsgBox は確かめて VBA の文言で抜ける)、全ヵ所/キャスク検査の表示中の HistorySave は DBflag を見ないこと、表の覚え方
